02

왜 그 모델을 골랐나

금융 업무에서는 성능보다 데이터가 어디서 처리되는지를 먼저 따졌습니다. 한 사람이 평균 3.4개의 이유를 들었습니다.

선택 이유

27명 · 복수 응답

  1. 1

    사내 실행 20명

    고객 정보와 미공개 자료를 외부 API로 보내지 않고 처리할 수 있습니다. 망분리 환경에서도 쓸 수 있고 호출 비용이 없습니다.

  2. 2

    한국어 특화 18명

    국내 공시·약관·리포트는 대부분 한국어입니다. 한국어 문서 검색에 맞춰 학습한 모델이 유리하다고 봤습니다.

  3. 3

    한·영 교차 검색 11명

    한국어로 질문해도 영문 리포트와 해외 공지를 함께 찾을 수 있습니다. 국내외 자료를 같이 보는 업무에서 중요했습니다.

  4. 4

    긴 문서 입력 10명

    수업 모델은 128토큰까지만 읽습니다. 8,192토큰 이상을 받는 모델은 약관과 투자설명서를 덜 잘게 나눠도 됩니다.

모델별 선택 이유

KURE-v321명

사내 실행, 한국어 검색 특화, 8,192토큰 입력, 한·영 교차 검색, Apache-2.0 라이선스. 약 1.1B 크기라 8B급 모델보다 운영 부담이 적습니다.

Gemini Embedding 22명

차트·표·PDF를 텍스트와 함께 색인하는 멀티모달 입력. 서버 구축 없이 API로 바로 시작할 수 있습니다.

BGE-M32명

다국어 원문(FOMC·중앙은행 성명서)에 적합. 의미 검색과 단어 검색을 한 모델에서 함께 씁니다.

Kanana-2 3B1명

전문 용어가 많은 한국어 문서 검색에 중점. 사내 서버에 둘 수 있습니다.

voyage-4-large1명

32,000토큰 초장문 입력. 로컬 경량 모델과 벡터 공간을 공유해 함께 운영할 수 있습니다.

수업 모델 공개일

KURE-v3 공개일

2026-10-20과 2026-10-16이 섞여 있었습니다. 공개 발표일과 API 스냅샷 ID에 들어 있는 날짜(20261016)는 다를 수 있습니다.

05

직접 실행해 보니

4명이 모델을 직접 돌려 봤습니다. 점수의 크기는 모델마다 달랐고, 순위와 점수 차가 더 믿을 만한 기준이었습니다.

관련 문장과 무관한 문장의 점수 차

한 실험의 결과 · 질문 1개와 금융 뉴스 문장 5개 · 클수록 잘 구분

점수가 낮아도 구분은 잘할 수 있습니다

KURE-v3는 코사인 유사도 값이 다른 모델보다 낮게 나왔지만, 관련 문장과 무관한 문장의 점수 차는 가장 컸습니다.

언어가 달라도 같은 뜻으로 읽는 모델이 있습니다

같은 내용의 한국어·영어 문장에 준 점수 차가 수업 모델은 0.268, Gemini Embedding 2는 0.003, KURE-v3는 0.027이었습니다.

128토큰을 넘으면 잘립니다

긴 약관 문장을 넣었을 때 수업 모델은 뒷부분의 수수료 조항을 읽지 못했습니다.

큰 모델은 느립니다

한 실험에서 KURE-v3의 임베딩 속도는 수업 모델보다 약 8배 느렸습니다. 대량 색인에는 GPU가 필요합니다.

06

보고서에 자주 나온 개념 6가지

코사인 유사도

문장을 숫자 벡터로 바꾸고, 두 벡터의 방향이 얼마나 비슷한지로 뜻의 가까움을 잽니다. 점수 범위는 모델마다 다르므로 한 모델 안에서의 순위와 차이를 봅니다.

최대 입력 길이와 청킹

모델이 한 번에 읽는 토큰 수를 넘는 부분은 잘립니다. 긴 문서는 조항·문단 단위로 나눠 넣습니다. 덩어리가 너무 크면 세부 내용이 약하게 반영됩니다.

query: / passage: 접두어

검색용 모델은 질문과 문서를 구분해 학습하기도 합니다. KURE-v3는 질문에 query:, 문서에 passage:를 붙여야 제 성능이 나옵니다.

차원 축소 (MRL)

벡터 앞쪽에 중요한 정보가 모이도록 학습해 앞부분만 잘라 써도 성능이 크게 떨어지지 않습니다. 저장 공간이 줄고, 자른 뒤에는 다시 정규화합니다.

Dense와 Sparse 검색

Dense는 표현이 달라도 뜻이 비슷한 문서를 찾고, sparse는 FOMC·VIX 같은 용어의 정확한 일치를 잡습니다. 둘을 합치면 금융 용어 검색에 유리합니다.

모델을 바꾸면 다시 임베딩

모델마다 벡터 공간이 다릅니다. 차원 수가 같아도 다른 모델의 벡터와는 비교할 수 없으므로 저장한 문서를 모두 새로 임베딩해야 합니다.

선택 이유와 활용 예시는 복수 응답으로 집계했습니다. 모델 사양과 날짜는 보고서에 적힌 값이므로 사용 전에 공식 문서에서 확인하세요.
