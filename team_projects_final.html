핵심 메시지

“사람은 적게 가지만, 볼 것은 있습니다.”

해결하려는 문제

여행 앱과 SNS는 인기순으로 보여주므로, 덜 알려진 지역이 정말 한산한지·가볼 만한 곳이 있는지 판단할 근거가 없음 → 실제 방문 데이터로 ‘덜 가는 곳’을, 관광지 사진으로 ‘볼 것이 있는지’를 같은 화면에서 확인

주요 화면 · 기능

  • 지도 — 방문량 5단계 코로플레스, 숨은 지역 후보 69곳 패널
  • 지역 상세 — Ghost Index, 하루 평균 방문, 전국 순위, 사진 6장
  • 관심 관광지 비교 — ♡로 담아 이용시간·쉬는날·주차·방문량 비교, 비교 링크 공유
  • 데이터 분석 — 차트 5개와 표 보기

데이터 출처

  • 한국관광공사 지역별 방문자수 (관광빅데이터) — 2026.8.2~31, 24,208행
  • TourAPI 국문 관광정보 — 사진 있는 관광지 17,658곳
  • SGIS 행정구역 경계 — 시 단위 230개 GeoJSON
  • 행정안전부 인구감소지역 명단 (비즈니스 분석용)

0.06사진 있는 관광지 수와 방문량의 상관계수 — 볼거리와 방문량은 거의 무관
98배지역 간 하루 방문량 차이 (영양군 6,432명 ↔ 강남구 631,565명)

“이번 주말에 뭐 하지?” → “이거 같이 갈래?”

해결하려는 문제

  • 정보가 흩어져 있다 — 공연·축제·전시 정보가 여러 곳에 있어 일정 비교가 어려움
  • 같이 갈 사람이 없다 — 마음에 드는 활동을 찾아도 결국 미루게 됨

주요 화면 · 기능

  • 활동 탐색 — 지역(서울·대전)·유형·날짜 필터
  • 지도 · 타임라인 — 지도에서 바로 모임 만들기
  • 활동 상세 · 모임톡 — 모임 참여, 메시지
  • QR 등록 · 라이브 보드 — 발표장에서 청중 참여
  • 통계 — KOPIS 통계, 인구 대비 비교, 데이터 품질
  • 사용자 활동 만들기 (러닝 등)

데이터 출처

  • KOPIS 공연예술통합전산망 — 공연, 공연 통계
  • 한국관광공사 TourAPI — 축제·행사
  • 한국문화정보원 — 전시
  • 행정안전부 주민등록 인구통계 — 인구 대비 비교

서비스 아키텍처

사용자QR 접속→HTML·CSS·JSVercel→FastAPIRender→PostgreSQLSupabase

수집은 POST /collect (토큰 필요) · 통계 GET /stats/* 6개 · GitHub Actions로 PR마다 테스트, 08~22시에는 10분마다 서버를 깨워 둠(keep-warm)

구성원 (4명)

핵심 메시지

“어디로 떠날지, 날씨까지 한 번에.”

해결하려는 문제

초보·가족·주말 캠퍼가 캠핑장과 날씨를 따로 찾아 비교해야 하는 수고 — “이번 주말 강원도에서 시설도 좋고 날씨도 맞는 캠핑장을 찾고 싶다.”

사용 흐름

① 탐색지역·날짜·유형 검색→② 확인카드·날씨 패널→③ 저장로그인 후 하트→④ 다시 보기내 플랜

데이터 출처

  • 한국관광공사 고캠핑 정보 조회서비스 (basedList)
  • 기상청 중기예보 — 3~10일 뒤 날씨·강수확률·기온
  • 기상청 단기예보 — 오늘~3일 뒤, 캠핑장 좌표 기준

서비스 아키텍처

React + TSVercel→FastAPIRender · 목록 캐시 1시간→고캠핑 · 기상청

로그인·플랜 저장은 브라우저 → Supabase Auth + PostgreSQL 직접 호출, 행 단위 보안(RLS)으로 본인 플랜만 조회·저장·삭제 · 공공데이터 키는 백엔드 환경변수에 보관

구현 규모

4API 엔드포인트 (/health · /api/regions · /api/campgrounds · /api/weather)
2DB 테이블 (camping_plans · regional_forecast_mapping)
17시·도 지역 분류
13~15분시나리오 시연 (화면 조작 → API 요청 → 코드 → 결과)

비즈니스 모델

사용자 기본 기능 무료, 수익안은 예약·용품 제휴와 광고 표시 유료 노출 — 팀이 ‘기획안’으로 명시했고 결제·광고·제휴 정산은 이번 구현 범위에 포함하지 않음. 캠핑장 목록 캐시로 요청량과 운영 비용 관리.
